# dm_job_bundle

Databricks Asset Bundle for `dm_job` — example output generated by the dabs-migrator skill.

> ⚠️ **Paused for staging and prod.** This bundle is safe to run in `dev` only.
> Staging and prod targets will be added after open issues are resolved:
> [#108](https://github.com/databricks-solutions/technical-services-solutions/issues/108).

## Before you use this project

Set your own values in `databricks.yml`:

| Placeholder | Replace with |
|---|---|
| `<your-dev-catalog>` | your dev Unity Catalog catalog name |

## Layout

```
dm_job_bundle/
├── databricks.yml          # bundle root (dev target only)
├── resources/
│   └── jobs/
│       └── dm_job.yml      # job resource definition
├── src/
│   └── dm_job/
│       └── notebook.py     # verbatim source from workspace
├── tests/
│   └── test_unity_catalog.py
├── requirements.txt
└── .gitignore
```

## Dev target — no binding needed

The first `databricks bundle deploy -t dev` creates a **new isolated dev copy** of `dm_job`
(named `[dev <user>] dm_job`). The original workspace job runs independently and is not affected.

Binding is only required for **staging and prod** source targets, where the goal is to
update the existing production asset rather than duplicate it.

> ⛔ **Never run `databricks bundle destroy`** — it will delete live workspace assets.

## Deploy

```bash
# First-time (after binding):
databricks bundle deploy -t dev

# Subsequent deploys:
databricks bundle deploy -t dev
```

## Local validation

```bash
databricks bundle validate -t dev
```
